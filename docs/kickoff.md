# Kickoff: замена демо-раздела реальными данными

Демо-карта описывает платежи, но код не привязан к этой предметной области.
Чтобы построить карту другого раздела, меняйте модули данных и проверяйте
результат тестами и экспортом.

## 1. Соберите входные данные

Для каждого экрана нужны:

- стабильный `id` в kebab-case;
- короткий код вида `// 01 / A`;
- заголовок и route;
- описание назначения;
- API endpoints;
- состояния интерфейса;
- поля: подпись, API name, тип, сущность и статус;
- начальная позиция, кратная сетке 10 px;
- признак центрального хаба, если экран является точкой входа.

Для каждой сущности нужны ключ, человекочитаемая подпись и иконка. Для каждого
перехода нужны экран/поле источника, экран/поле приемника и пояснение смысла связи.

## 2. Отредактируйте модули

- `src/data/screens.ts` - `SCREENS` и производные индексы.
- `src/data/entities.ts` - `ENTITY_META`.
- `src/data/edges.ts` - `EDGE_DEFS`.
- `src/data/status.ts` - палитра, если набор статусов другой.
- `src/data/constants.ts` - только если меняется геометрия или путь раздела.

Не добавляйте данные прямо в компоненты. Компоненты получают экраны и поля из
модулей данных и store.

## 3. Проверьте инварианты

```bash
npm test
npm run typecheck
npm run export:schema
npm run test:e2e
```

Обратите внимание:

- id экранов уникальны;
- в одном экране одна сущность соответствует одной строке поля;
- каждое ребро ссылается на существующие экран и сущность;
- ключ сущности одинаков на обоих концах маршрута;
- позиции не выводят карточки за пределы холста 1200 x 900 без причины;
- экспорт содержит ожидаемые counts screens, fields, entities и edges.

## 4. Визуальная проверка

```bash
npm run dev
```

Проверьте hover каждого ключевого маршрута, спецификацию каждого экрана,
контекстное меню, ELK и сброс. Если ELK раскладывает новый граф неудачно,
сначала проверьте направления и дубли ребер в данных, а не CSS.

## 5. Стартовый бриф для AI Assistant

Перед работой агент должен прочитать `.aiassistant/rules/AI Rules.md`, README и
этот файл. В брифе укажите:

- название и границы раздела;
- список экранов и маршрутов;
- сущности, которые должны светиться как единый маршрут;
- статусы и их бизнес-смысл;
- какой экран является хабом;
- ограничения по геометрии и текстам;
- какие сценарии обязательно покрыть e2e.

Пример запроса:

```text
Замени демо-платежи на раздел <name>. Экраны: <list>. Хаб: <screen>.
Сущности и маршруты: <list>. Сохрани геометрию 1200 x 900, сетку 10 px,
field -> field связи и экспорт JSON. Обнови данные, тесты, README и скриншоты.
```

## 6. Перед коммитом

```bash
npm run format:check
npm run lint
npm run lint:css
npm run lint:md
npm run check:file-length
npm run check:docs
npm run build
```

Если изменился публичный набор данных, перегенерируйте образец экспорта и
обновите скриншоты в `screenshots/` в том же логическом изменении.
