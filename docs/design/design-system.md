# Дизайн-система экрана карты — направление B (слоёный продуктовый UI)

Дата: 2026-10-21
Статус: на утверждении
Затрагивает: `src/features/screen-map/styles/**`, инлайновые цвета в `ui/**` и `ScreenMapPage.tsx`

## 1. Зачем

Слой оформления — это 12 CSS-файлов (~1225 строк) с двумя CSS-переменными
(`--font-sans`, `--font-mono`) и сотней с лишним захардкоженных hex-значений. Один и тот же
«почти чёрный» (`#1e1e1e`, `#1f1f1f`, `#222`, `#232323`, `#242424`) означает в разных местах
то границу, то фон, то hover; текстовая шкала не задана; радиусы, размеры шрифта и отступы
не масштабируются; тени — одна на весь проект; состояния фокуса не видно ни на одном
интерактивном элементе.

Цель: ввести слой токенов и перерисовать интерфейс в одном согласованном направлении.
Библиотеки примитивов не меняются, новых зависимостей нет.

## 2. Решение по направлению

Выбрано направление **B** — «слоёный продуктовый UI»: холодная slate-палитра, крупные
радиусы, глубина через тень и внутренний хайрлайн, акцент — indigo. Логика подсмотрена
в Untitled UI: семантические поверхности, единый шаг времени, фокусное кольцо 2px + 2px.

Прототип трёх направлений: `design.html` + `design/`. Это временные файлы, в сборку
не входят. Удаляются последним шагом, после визуальной сверки (10.5).

### Решения владельца

- Акцент — **indigo `#5f62f0`**: заливка основной кнопки, выбранного фильтра статуса,
  кольца фокуса. Нейтральная белая кнопка, как сейчас, не сохраняется. Оттенок выбран
  по требованию WCAG AA: белый текст на `#6366f1` давал 4.47:1 при пороге 4.5, у
  `#5f62f0` — 4.68:1.
- Тема — **только тёмная**. Токены структурированы так, чтобы светлая тема добавилась
  позже переопределением блока, но в этот заход она не входит.
- Типографика — **новая шкала** 11 / 12 / 13.5 / 16 px вместо текущих
  10 / 11 / 11.5 / 12.5. Следствие: ширина карточки зафиксирована на 232 px, поэтому
  длинные заголовки экранов уходят в ellipsis (см. 4.1).

## 3. Границы задачи

### Входит

- Слой токенов как единственный источник визуальных значений в CSS.
- Перерисовка всех 12 CSS-файлов на токенах в стиле B.
- Перенос инлайновых цветов из TSX в CSS.
- Темизация React Flow: сетка, мини-карта, контролы, атрибуция, связи, порты.
- Видимые состояния фокуса (`:focus-visible`) на всех интерактивных элементах.
- Регрессионный тест: значения спецификации не разъезжаются с TS-константами, а сырых
  цветов вне `tokens.css` не остаётся.

### Не входит

- Новые runtime-зависимости. Base UI, React Flow, cmdk, lucide, Geist — без изменений.
- React Aria, Untitled UI, Tailwind: идеи взяты, код не используется.
- Изменение DOM-структуры, логики компонентов, поведения и клавиатурной навигации.
- Изменение семантики экспортируемого JSON (см. 4.1).
- Светлая тема. Токены структурированы так, чтобы её можно было добавить позже
  переопределением блока, но сама тема — вне объёма.
- Редизайн содержания: подписи, формулировки, состав экранов.

### Что считать провалом

- Изменение геометрии карточки. Раскладка ELK и экспорт считают размеры по TS-константам,
  поэтому лишний пиксель в CSS не виден в diff-е JSON, но ломает раскладку.
- Токены, которые объявлены, но не используются.
- Сырые hex/rgb-значения вне `tokens.css`.
- Расхождение между экспортируемым JSON и тем, что нарисовано на экране.

## 4. Ограничения

### 4.1 Значения, зафиксированные спецификацией (менять нельзя)

Они попадают в экспортируемый JSON, поэтому экран обязан рисоваться ровно тем же.

- Холст 1200×900, сетка 10 — `CANVAS`, `data/constants.ts:5`.
- Фон холста `#111` — `CANVAS.bg`, `constants.ts:5`; применяется в `ScreenMapPage.tsx:112`.
- Ширина карточки 232 — `NODE_W`, `constants.ts:9`.
- Шапка 40, строка 23, скелетон 30, chrome 13 — `HEAD_H`, `ROW_H`, `SKEL_H`, `CHROME_H`,
  `constants.ts:10-13`.
- Точка порта 5 — `PORT_SIZE`, `constants.ts:14`.
- Иконка поля 12 — `components["card/field"].icon`, `data/export.ts:118`.
- Связь: orthogonal, dash `3 4`, цвет `#7C7C7C`, скругление 8 (норма 7–9) — `EDGE_STYLE`,
  `constants.ts:15-20`.
- Подпись: mono 10px, tracking `.11em`, цвет `#5A5A5A` — `meta.caption`, `data/export.ts:121`.
- Цвета статусов: new `#A78BFA`, sent `#66D97A`, pending `#E6D24F`, failed `#F0788A`,
  none `#3D3D3D` — `STATUS`, `data/status.ts:4-10`.

Следствия:

- Подпись в стиле B остаётся `#5A5A5A` mono 10px, а цвет связи — `#7C7C7C`. Они не переезжают
  в slate-шкалу. Скругление связи — 8px, отдельный токен, а не `--r-lg`.
- Высота карточки обязана остаться ровно `HEAD_H + строки×ROW_H + (скелетон? SKEL_H : 0) +
CHROME_H` (`data/screens.ts:9`). Значит: `box-sizing: border-box` обязателен, внутри
  `.scr` нельзя добавлять `gap`, лишние рамки или padding. Рамки поглощаются border-box.
- Ширина карточки 232 — узкая. Заголовок экрана (`white-space: nowrap`) обязан получить
  `min-width: 0` и `text-overflow: ellipsis`, иначе длинные названия вылезут за карточку.
- Приглушение поля (`opacity: 0.2` в неактивном маршруте) проверяется e2e
  (`tests/e2e/screen-map.spec.ts`, строка 60 — `toHaveCSS("opacity", "0.2")`). Значение обязано
  остаться ровно `0.2`; переносить его в токен можно, менять нельзя.

### 4.2 Гейты репозитория

  (`selector-class-pattern`, `custom-property-pattern`), современная нотация цвета
  (`rgb(0 0 0 / 30%)`), процентная альфа.
- `npm run format:check` — prettier, printWidth 120.
- `npm run lint` — ESLint, включая `max-lines` 250 для TS/JS.

- `npm run lint:md` — markdownlint, включая `MD013` (120 колонок) и `MD060` (выровненные
  таблицы). Это относится и к документам в `docs/`.
- `npm run check:docs` — документация должна оставаться согласованной.
- `npm run build` — собирается только `index.html`; корневые `design.html` и папка `design/`
  в бандл не попадают.

### 4.3 Технические

**Переменные и атрибуты.** `var()` работает в инлайновых стилях React, в CSS-декларациях и
в `style` SVG-элементов, но **не** в SVG-атрибутах-presentation (`stroke="var(--x)"`).
При этом CSS-декларация побеждает presentation-атрибут, поэтому цвет, заданный React
через атрибут, переопределяется правилом по классу.

**Темизация React Flow v12.** У библиотеки есть штатные переменные темы:

```css
--xy-background-pattern-color      сетка
--xy-edge-stroke, --xy-connectionline-stroke
--xy-attribution-background-color
--xy-minimap-background-color, --xy-minimap-mask-background-color
--xy-minimap-node-background-color, --xy-minimap-node-stroke-color
--xy-handle-background-color
--xy-controls-button-background-color, --xy-controls-button-color
--xy-controls-button-border-color, --xy-controls-box-shadow
```

Правила библиотеки устроены так: `var(--xy-*-props, var(--xy-*, default))` — то есть
значение, переданное пропом компонента, перебивает нашу переменную. Отсюда:

- `<Background color={...}>` задаёт `--xy-background-pattern-color-props`. Чтобы цвет сетки
  шёл из токена, проп `color` убирается, а в CSS задаётся `--xy-background-pattern-color`.
- `MiniMap nodeColor/nodeStrokeColor` — инлайновые `style` на `<rect>`, их не перебить
  правилом по классу. Пропы остаются (различие hub/остальные), но значения передаются
  строками `var(--minimap-node-hub)` / `var(--minimap-node)` — в инлайновых стилях `var()`
  разрешается.
- Иконки контролов рисуются `fill: currentColor`, поэтому нынешний `fill: #bdbdbd` на
  `.react-flow__controls-button` — мёртвый код. Управлять надо `color`, `background` и
  `border-bottom`.

## 5. Токены

### 5.1 Контракт

Один блок в `:root`, разбитый на секции. Имена семантические, как в Untitled UI:
поверхности, текст, границы, высота, радиусы, типографика, отступы, движение, фокус.

```css
/* поверхности */
--bg-canvas        фон вокруг холста
--bg-surface       карточка экрана, поверхность поля ввода
--bg-raised        топбар, инспектор, попапы, тосты
--bg-sunken        chrome-полоса, порты, kbd, утопленные блоки
--bg-hover         наведение на строку поля, пункт меню
--bg-active        нажатое или выбранное
--bg-accent        заливка акцентных элементов
--bg-accent-hover
--bg-accent-soft   полупрозрачная подложка акцента
--bg-glass         полупрозрачная панель поверх холста (88%)

/* текст */
--fg               основной
--fg-muted         вторичный
--fg-subtle        третичный, entity-ключи
--fg-on-accent     текст на акценте
--fg-accent        акцентный текст на тёмном

/* границы */
--border-subtle    разделители внутри блоков
--border           обычная граница
--border-strong    выделенная граница, hover
--border-accent

/* высота */
--shadow-card      тень карточки
--shadow-popup     тень попапа
--ring-inset       внутренний хайрлайн: inset 0 1px 0 rgb(255 255 255 / 5%)

/* радиусы */
--r-sm 4px   --r-md 8px   --r-lg 12px   --r-xl 16px   --r-pill 999px
--r-edge 8px                      /* спецификация: норма 7-9 */

/* типографика */
--t-xs 11px  --t-sm 12px  --t-md 13.5px  --t-lg 16px  --t-xl 20px
--caption-size 10px                /* спецификация */
--caption-tracking 0.11em         /* спецификация */
--caption-color                    /* спецификация: #5A5A5A */

/* геометрия: зеркалит TS-константы, проверяется тестом */

/* наложения */
--overlay-scrim           затемнение под диалогом
--overlay-soft            подсветка строки поля
--scrollbar-thumb, --scrollbar-thumb-hover

/* React Flow */
--grid-line               линии сетки
--connection-stroke
--edge-color              /* спецификация: #7C7C7C */
```

Ширина карточки в CSS не нужна: `NODE_W` применяется инлайном в `ScreenNode.tsx:26`.
В токены вынесен только размер иконки — через `.fld svg { width: var(--icon-size) }`.

### 5.3 Геометрия: один источник

Сейчас высота строки поля (23px) задана в двух местах: `ROW_H` в `constants.ts` и
`.fld { height: 23px }` в `field.css`. То же с портом, иконкой, шапкой, скелетоном,
chrome-полосой.

Решение: в `tokens.css` появляется блок `--head-h/--row-h/--skel-h/--chrome-h/--port-size/
--icon-size` со значениями из спецификации, CSS использует только их, а тест (5.4)
сверяет токены с TS-константами. Расхождение → падение теста.

### 5.4 Тест на согласованность

Новый файл `src/features/screen-map/styles/tokens.test.ts` (vitest подхватывает:
include `src/**/*.{test,spec}.{ts,tsx}`). Читает CSS как текст, регуляркой, без новых
зависимостей. Проверяет:

1. **Токены против TS.** `--head-h/--row-h/--skel-h/--chrome-h/--port-size/--icon-size`
   против `HEAD_H`, `ROW_H`, `SKEL_H`, `CHROME_H`, `PORT_SIZE` из `constants.ts` и
   `buildExport(...).meta.components["card/field"].icon` (это литерал внутри `export.ts`,
   а не константа — константу вводить нельзя, она попадёт в экспорт).
2. **Подпись.** `--caption-size` и `--caption-tracking` против `meta.caption` из
   `buildExport(...)`. Нормализация: `.11em` и `0.11em` считаются равными.
3. **Связь.** `--edge-dash` и `--r-edge` против `EDGE_STYLE` из `constants.ts`;
   `--r-edge` обязан лежать в диапазоне 7–9.
4. **Статусы.** `--status-*` в `tokens.css` против `STATUS` из `data/status.ts`.
5. **Сырые цвета.** В 11 CSS-файлах, кроме `tokens.css`, не должно быть ни hex-значений,
   ни `rgb(`/`rgba(`. Это ловит дублирование, которое проверка токенов пропускает.
   Точечные исключения — если билдеру понадобится — оформляются списком в самом тесте.

Проверка 5 — самая важная: без неё «единственный источник истины» остаётся пожеланием.

### 5.5 Раскладка файлов

- `src/features/screen-map/styles/tokens.css` — новый, первым импортом в `index.css`.
  Комментарии делят токены на секции; тема добавляется блоком `[data-theme="..."]` ниже.
- Остальные 11 файлов переписываются на токены. Структура и имена классов сохраняются:
  меняются значения и добавляются состояния. DOM-контракт не меняется.
- `index.css` — порядок импортов: `tokens.css` первым, остальное как есть.

## 6. Идеи, которые берём у Untitled UI

- Семантические поверхности вместо буквальных цветов: `--bg-surface` вместо `#161616`.
- Глубина без тяжёлых теней: `--ring-inset` на карточках и кнопках.
- Фокусное кольцо 2px и offset 2px: `--focus-ring` на всех интерактивных элементах.
- Единый шаг времени: `--dur-fast` на hover и press, `--dur-base` на смену состояний.
- Явные состояния: `:hover`, `:active`, `:focus-visible`, `[data-pressed]`, `[data-highlighted]`.
- Порядок слоёв: `shadow` + `inset` + `border` в одном правиле, а не по одному.

## 7. Инлайновые цвета в TSX — уезжают в CSS

- `ui/FieldRow.tsx:44-45` — порт: `#141414` и `#6E6E6E`. Уезжают в `.port` в `field.css`.

- `ScreenMapPage.tsx:114` — сетка React Flow `#1D1D1D`. Проп `color` убирается,

## 11. Решения, принятые при реализации

Расхождения спецификации, зафиксированные по ходу работ.

- **Кольцо точки статуса.** Точки статуса выросли до 8px (`.dot`) и 7px
  (`.scr-dots i`) и получили обводку `--fg-subtle`: 3.69:1 на `--bg-surface` и
  3.89:1 на `--bg-sunken`. Без обводки статус `none` (`#3D3D3D`) не виден —
  контраст 1.5:1. Вариант с `--border-strong` отклонён: 1.75:1 не хватает.
- **Обрезка панели инспектора.** Base UI задаёт `min-width: fit-content` инлайном
  на содержимом скролл-контейнера, из-за чего содержимое инспектора выходило за
  панель и обрезалось. Дефект существовал до редизайна. Исправлено правилом
  `min-width: 0 !important` для `.inspector-content` в `inspector-rows.css`.
- **Пропы мини-карты.** У `MiniMap` сняты не только `nodeColor` и `nodeStrokeColor`,
  но и `bgColor` и `maskColor`: они задают `--xy-minimap-*-props`, которые перебивают
  наши переменные. Теперь цветами мини-карты управляют только токены.
- **Скругление связи и её тире.** В `OrthEdge.tsx` литералы `8`, `"3 4"` и `"#7C7C7C"`
  заменены на `EDGE_STYLE.cornerRadius`, `EDGE_STYLE.dash` и `EDGE_STYLE.color`:
  экспортируемый `meta.edgeStyle` и нарисованная связь берут одно значение.
- **Реакция на движение.** Добавлен блок `@media (prefers-reduced-motion: reduce)`,
  отключающий анимации и переходы в интерактивных элементах, шаблоне карточки и
  «марширующей» подсветке рёбер.
- **Выделение активного пункта.** В меню и командной палитре выделенный пункт должен
  отличаться от остальных не только фоном (разница 1.13–1.18:1, ниже порога WCAG
  1.4.11), но и текстом. Поэтому обычный пункт получил `--fg-muted`, а выделенный —
  `--fg`. Активный фильтр в легенде статусов помечен акцентом: `--border-accent`,
  `--fg-accent`, `--bg-accent-soft`.
- **Фон холста.** React Flow рисует свой `<svg class="react-flow__background">` поверх
  инлайнового `background` контейнера, поэтому заявленный в экспорте `#111` на экране
  не был виден: рисовался дефолт библиотеки. Добавлен токен `--canvas-bg` (зеркало
  `CANVAS.bg`) и переменная `--xy-background-color`, тест сверяет их с экспортом.
- **Шапка карточки.** Высота 40 px зафиксирована спецификацией, а содержимое
  (подпись 10 px + заголовок 13.5 px) в неё не помещалось. Поджаты отступы
  (`5px 10px 4px`), у заголовка убран `margin-top` и задан `line-height: 1.2`.
  Проверено замером: `scrollHeight` шапки равен `clientHeight`.
