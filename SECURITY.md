# Security Policy

## Поддерживаемые версии

Проект развивается как одностраничное приложение без серверной части.
Исправления безопасности выпускаются для актуальной версии в основной ветке;
старые snapshot-сборки не поддерживаются.

## Как сообщить об уязвимости

Не публикуйте детали уязвимости в обычном issue до исправления. Если репозиторий
размещен на GitHub, используйте Private Vulnerability Reporting:

1. Откройте вкладку `Security`.
2. Нажмите `Report a vulnerability`.
3. Укажите шаги воспроизведения, влияние, затронутые файлы и предложение по fix.

Если приватный канал недоступен (например, копия репозитория без remote), передайте
отчет владельцу репозитория вне публичного трекера и не публикуйте детали в issue.
Целевой срок первого ответа - 7 дней.

## Что входит в область политики

- Исходный код приложения и генерация экспортируемого JSON.
- GitHub Actions workflow, Git-хуки и служебные скрипты.
- Конфигурации линтеров и кастомные правила, если они могут выполнить небезопасный код.
- Утечка секретов в репозиторий, логи CI или production bundle.

## Что не входит

- Данные реального раздела, которые пользователь сам вставил в локальные модули.
- Уязвимости сторонних npm-пакетов без эксплуатируемого пути в этом проекте:
  их следует сообщать upstream, а обновления приходят через Dependabot.
- Настройки хостинга, CDN, CSP и reverse proxy вне этого репозитория.

## Состояние npm audit на 2026-10-21

- `npm audit --omit=dev`: 0 уязвимостей. Production bundle не содержит
  известных уязвимых пакетов по данным npm audit.
- Полный `npm audit`: 10 находок в dev-дереве, все high. Все находки
  сходятся к транзитивной цепочке Stylelint -> globby/fast-glob/micromatch ->
  braces и advisory о stack-exhaustion DoS на глубоко вложенных glob-паттернах.
- Для корневой уязвимости `braces` npm audit не предлагает исправленной версии.
  Риск ограничен локальным запуском Stylelint на недоверенных паттернах и не
  попадает в production bundle.
- Остальные находки закрыты принудительными версиями в `overrides`:
  `js-yaml` 5.5.0 (было 5.2.3), `smol-toml` 1.9.1 (было 1.7.2) и `katex` 0.18.10
  (было 0.16.47). Это dev-инструменты, production bundle их не содержит.

Не запускайте линтеры и генераторы на недоверенном checkout без изоляции: npm
scripts, Git hooks и конфигурации инструментов по определению выполняют код.

## Меры в репозитории

- CI имеет только `contents: read`.
- В CI задан `HUSKY=0`, чтобы установка зависимостей не меняла Git-конфигурацию.
- GitHub Actions закреплены на commit SHA, а не на изменяемых тегах.
- Dev- и preview-серверы по умолчанию слушают только loopback (`127.0.0.1`).
  Доступ из локальной сети включается явно через `npm run dev:lan` и
  `npm run preview:lan`; проверка `Host`-заголовка при этом остается включенной.
- Dependabot ежемесячно проверяет npm и GitHub Actions.
- Секреты не нужны приложению и не должны добавляться в `.env` коммиты.
- Экспортируемый JSON формируется локально в браузере из состояния карты.
